# 胡桃音乐 Apple Music 风格桌面 UI 重构设计

**日期：** 2026-08-07  
**状态：** 已确认设计，待实现计划  
**范围：** hmp-desktop Slint UI、桌面桥接模型和必要的 AppCore UI 数据接口

## 1. 目标

将现有 hmp-desktop 重构为一个信息架构清晰、可长期使用、风格接近 Apple Music 的 Linux 桌面播放器界面，同时保留并回归验证当前已经可用的 QQ 音乐登录、搜索、播放、暂停、上一首、下一首、Seek 和音量能力。

本次重构采用“资料库优先”的默认体验，新增资料库、推荐、搜索、队列、歌词、设置/关于等页面和统一导航。推荐、收藏与资料库同步等尚未具备完整后端能力的区域必须明确标记为开发中，不得用演示数据伪装成真实账号数据或返回虚假的成功结果。

## 2. 已确认的产品边界

### 2.1 真实接入

- QQ 音乐扫码登录和登录状态展示。
- QQ 音乐搜索。
- 搜索结果播放。
- 播放、暂停、上一首、下一首。
- 播放进度显示、Seek 和音量控制。
- 当前播放状态和播放队列的桥接展示。
- 当前曲目歌词的状态入口；有真实歌词数据时展示，暂无数据时展示空状态。

### 2.2 演示或开发中

- 推荐页使用稳定的本地中文演示数据，不发起推荐网络请求。
- 收藏、云端歌单同步、完整资料库同步保持页面骨架和空状态，显示“开发中”状态条。
- 队列中的移除、清空、拖动排序等操作只有在对应 AppCore 命令存在并完成验证后才启用；未接入时保持禁用，不模拟成功。
- 歌词的网络请求和逐行同步如果现有核心没有提供数据，则只实现真实状态模型和空状态，不制造歌词内容。

## 3. 信息架构

### 3.1 默认路由

应用启动后默认进入“资料库”。首次启动没有登录凭据、播放历史或队列时，资料库显示稳定的空状态，并提供进入搜索页的操作。导航切换不停止或重置当前播放。

页面路由使用明确的枚举或字符串常量，至少包含：

```text
library
recommend
search
queue
lyrics
settings
```

播放栏中的队列和歌词按钮直接切换到对应页面。页面切换属于 UI 状态，不通过网络请求，也不改变 PlayerCore 的权威播放状态。

### 3.2 页面职责

**资料库**

展示当前曲目、当前队列、最近播放或本地可推导的播放信息。收藏、云端歌单和同步区域使用开发中状态条或空状态。资料库不得把本地演示推荐数据显示为用户收藏。

**为你推荐**

展示本地演示数据，包括精选专辑/歌单、最近播放风格的推荐区和歌曲列表。页面顶部显示低干扰的开发中状态条，文案明确该页面当前使用演示数据。演示歌曲可以触发已有播放入口时，必须使用真实可播放的搜索结果或明确保持为浏览展示，不能承诺不存在的后端能力。

**搜索**

保持现有真实搜索链路。支持未搜索、加载、成功、无结果和失败状态。空关键词不发起请求。结果列表支持点击播放，并将当前结果集作为 AppCore 的播放队列。

**队列**

展示 AppCore 当前队列、当前项和播放状态。当前项需要有可见但低干扰的播放指示。队列为空时提供进入搜索页的操作。底层没有实现的队列修改能力显示为禁用状态，并在设置/关于页记录为开发中。

**歌词**

展示当前曲目标题和歌词状态。状态至少包括未播放、加载中、已有歌词、无歌词、加载失败。已有歌词数据时使用逐行模型，保留原文和可选译文字段；没有数据时显示真实空状态，不内置伪造歌词。

**设置/关于**

提供主题模式选择和功能状态矩阵。主题模式为跟随系统、浅色、深色。功能矩阵至少列出登录、搜索、播放、队列展示、歌词展示、推荐内容、收藏与资料库同步，并分别标识“已接入”“部分接入”“开发中 / 演示数据”。

## 4. 视觉系统

### 4.1 主题

使用语义化主题变量，不在页面组件内直接散落深色或浅色硬编码颜色。两套主题共享相同的变量名和布局尺寸。

深色主题：

- 内容区为近黑灰背景。
- 侧栏比内容区更深一层。
- 主文字接近白色，次文字为中性灰。
- 强调色沿用现有胡桃音乐红色 `#ff2d55`。
- 分隔线使用低对比度中性灰。

浅色主题：

- 内容区为白色或极浅中性灰。
- 侧栏使用略深的冷灰白。
- 主文字为深灰黑，次文字为中灰。
- 强调色仍为 `#ff2d55`，必要时调整文字与背景组合以保证可读性。

默认模式跟随系统。若 Slint 1.17 的公开 API 不提供当前项目所需的系统配色读取方式，实现可先将跟随系统映射为启动时检测到的主题，并将检测逻辑隔离在 Rust UI 状态层，不能在各页面复制平台判断。

### 4.2 布局与组件规则

- 目标窗口尺寸为 `1100x720`，设置合理的最小尺寸，所有固定格式控件使用稳定宽高或布局约束。
- 主窗口为左侧导航、中间内容区、底部常驻播放栏三层结构。
- 普通歌曲列表使用行式布局、悬停背景和分隔线，不使用层层嵌套卡片。
- 卡片仅用于推荐内容、登录面板等确实需要被框定的重复内容。
- 播放主按钮为圆形强调按钮；其他播放工具使用统一图标按钮组件。
- 封面使用固定尺寸、统一小圆角和稳定占位图，图片失败不能引起布局偏移。
- 窄窗口收窄侧栏并隐藏次要文字；不设计移动端布局。
- 所有按钮、状态条和列表文字必须在默认和最小窗口尺寸中不溢出、不相互遮挡。

### 4.3 “开发中”呈现

未完成页面顶部统一显示低干扰状态条：

```text
开发中 · 当前页面使用演示数据或部分真实数据
```

页面内容仍可浏览，但任何未接入的修改操作不得伪装成可用。设置/关于页提供完整功能矩阵，作为项目当前能力的记录入口。

## 5. 组件边界

将当前过大的 `crates/hmp-desktop/ui/app.slint` 拆分为以下职责明确的文件：

```text
crates/hmp-desktop/ui/
├── app.slint              # 根窗口、页面路由和全局状态绑定
├── theme.slint            # 深色/浅色语义色与尺寸令牌
├── primitives.slint       # 图标按钮、封面、开发中条、空状态
├── sidebar.slint          # 侧栏导航与账号区
├── library-page.slint     # 资料库页面
├── recommend-page.slint   # 推荐演示页面
├── search-page.slint      # 真实搜索页面
├── queue-page.slint       # 播放队列页面
├── lyrics-page.slint      # 歌词页面
├── settings-page.slint    # 设置、主题选择和功能矩阵
├── player-bar.slint       # 常驻底部播放栏
└── login-dialog.slint     # 登录二维码模态层
```

`AppWindow` 只负责组合这些组件、持有跨页面属性和转发回调。页面组件不直接访问 Rust、Cookie、API 客户端或播放器实例。

## 6. UI 数据与桥接接口

Slint 结构应保持扁平、可序列化地映射到 Rust，具体命名需在实现计划中固定并在桥接测试中验证。设计所需的最小结构如下：

```text
UiNavigation {
    current_page: string,
    theme_mode: string,
}

UiQueueItem {
    title: string,
    artist: string,
    duration: string,
    is_current: bool,
    is_playing: bool,
}

UiLyricLine {
    time: string,
    text: string,
    translation: string,
    is_active: bool,
}

UiLibraryItem {
    kind: string,
    title: string,
    subtitle: string,
    status: string,
}
```

应用命令分为两类：

- 纯 UI 命令：导航切换、主题模式切换。
- 应用核心命令：搜索、播放队列项、播放控制、Seek、音量、登录、歌词请求以及已实现的队列修改。

现有 `AppCommand`、`AppEvent` 和 `PlaybackState` 继续作为真实业务入口。新增 UI 状态不得复制 `PlayerCore` 的播放进度或歌曲权威信息。Rust 异步任务更新 UI 时继续通过 Slint 的 UI 线程调度机制或已持有的 `Weak<AppWindow>` 完成，不能从后台任务直接操作 UI 对象。

## 7. 状态与错误处理

### 7.1 搜索

状态：未搜索、加载中、成功、无结果、失败。失败消息必须可读，并提供重新搜索入口。空字符串和全空白关键词不发送 `AppCommand::Search`。

### 7.2 登录

状态：未登录、等待扫码、已扫码待确认、二维码过期、登录失败、已登录。二维码弹层可以取消，取消后不改变当前播放和搜索结果。

### 7.3 播放与队列

播放状态继续由 `PlaybackState` 发布。UI 只展示状态，不自行计算播放进度。队列展示从 AppCore 的真实队列快照映射而来；空队列显示搜索入口。

### 7.4 歌词

无当前曲目时显示未播放；有当前曲目但未取得歌词时显示无歌词；网络或解析错误显示加载失败。没有真实歌词数据时不能填充演示歌词。

### 7.5 封面

网络封面失败或为空时使用稳定占位图。图片加载不能改变封面容器尺寸，也不能阻塞其他页面渲染。

## 8. 测试与验收

### 8.1 自动化测试

使用现有 `i-slint-backend-testing` 和桥接测试模式覆盖：

- 导航回调产生正确页面状态或命令。
- 主题模式切换更新语义主题状态。
- 搜索模型正确映射标题、歌手和时长。
- 队列模型正确标识当前项和播放状态。
- 歌词模型正确映射原文、译文和激活行。
- 开发中状态条在推荐、收藏和未完成资料库区域显示。
- 登录二维码、登录完成和登录取消状态正确更新。
- 现有播放、Seek、音量、上一首、下一首和搜索回归测试继续通过。

### 8.2 命令


### 8.3 手动验收

在 Linux 桌面实际启动应用，至少检查：

- 默认进入资料库。
- 深色、浅色、跟随系统三种主题。
- `1100x720` 和最小窗口尺寸下的布局。
- 侧栏导航和播放栏常驻行为。
- 搜索真实结果、点击播放、队列展示和当前项突出显示。
- 登录二维码弹层的打开、取消、错误和完成状态。
- 推荐页的演示数据和开发中状态条。
- 歌词无数据时的空状态。
- 长标题、长歌手名、无封面和失败图片不造成文本溢出或布局重排。

## 9. Slint 1.17 API 约束记录

实现前已查询 Slint 1.17 官方文档和本地 `1.17.1` 源码，计划阶段仍需以项目锁定版本的编译结果为准核对具体 API：

- 当前 crate 固定使用 `slint = "1.17"`，构建脚本通过 `slint_build::compile("ui/app.slint")` 编译 UI。
- Rust 到 Slint 的模型使用现有的 `ModelRc` 和 `VecModel` 映射方式；跨线程数据必须回到 UI 线程后再更新。
- 后台任务更新窗口状态使用 `Weak<AppWindow>`，不得持有窗口强引用造成生命周期问题。
- 登录弹层优先使用 Slint 组件内的模态层或公开 popup 能力；不直接依赖 Slint 内部 `i_slint_core` 类型。
- 系统主题读取和标准控件样式 API 必须以 Slint 1.17 的公开文档为准。若文档路径或公开接口与最新文档不同，以 `Cargo.lock` 对应的 1.17.1 编译 API 为准，并在实现中保留平台检测隔离。

参考资料：

- Slint 1.17 发布说明：https://slint.dev/blog/slint-1.17-released
- Slint 官方文档：https://docs.slint.dev/latest/docs/slint/
- Slint std-widgets 文档：https://docs.slint.dev/latest/docs/slint/reference/std-widgets/overview/
- Slint Rust `ModelRc` 文档：https://docs.rs/slint/1.17.1/slint/struct.ModelRc.html
- Slint Rust `invoke_from_event_loop` 文档：https://docs.rs/slint/1.17.1/slint/fn.invoke_from_event_loop.html

## 10. 非目标

本次 UI 重构不包含：

- QQ 音乐 API 协议重写。
- 播放后端替换或 GStreamer 架构变更。
- MV、社区、评论、直播、播客、K 歌等业务。
- 真实推荐、收藏云同步和完整用户歌单接口实现。
- Windows、macOS 或移动端适配。
- 以演示数据替代真实账号数据。
