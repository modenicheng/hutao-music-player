## 里程碑 E：Local Library domain（最大）

**目标**：真正的本地媒体库闭环（审计"媒体库缺口"整节）：一等浏览入口、实体身份、文件生命周期。
**现状锚点**：
- `crates/hmp-storage/src/db.rs`：`tracks` 表（source/source_key/title/album/artist 单字符串/duration_ms/cover_uri/qq_song_id/bitrate?/sample_rate?——需核实列）；`local_files` 表（scan 用，ON CONFLICT(path) DO UPDATE，无删除）。
- `crates/hmp-storage/src/local.rs`：`is_audio_ext`（含 ape/aiff）、`LocalMeta`（lofty 提取）。
- `crates/hmp-cli/src/scan.rs`：`scan_dir` 递归 upsert；无 watcher、无 missing 标记。
- 所有本地曲 `ArtistId("local")`/`AlbumId("local")` 共享——身份碰撞（id.rs）。
**子任务**：
1. **实体建模**：`LibraryTrackId`（或 tracks.id 即身份）；`ScanRoot`（root 表：path/canonical/last_seen_generation）；`local_files` 加 `mtime_ns`、`size`、`last_seen_generation`；tracks 加列：多 artist（artist 改为表或 JSON？**决策点**）、album_artist、track/disc number、year、genre、embedded artwork（lofty 提取存 BLOB 或封面文件）。
2. **扫描生命周期**：全量扫描结束后 `UPDATE local_files SET missing=1 WHERE last_seen_generation < 本次`；`missing` 与"外接盘离线"区分（不自动删行，UI 标缺失）；`hmp scan` 增量（mtime_ns+size 跳过）。
3. **浏览入口**：`library tracks [--search] [--artist] [--album]`、`library albums`、`library artists` CLI + storage 查询（GROUP BY album/artist；artist 多值拆表后 join）。
4. **身份**：引入 `local_file_id`（canonical path + mtime/size 指纹）避免移动即"新歌"；非 UTF-8 文件名用 `OsStr` 原字节处理（`path.display()` 有损——storage 用 `to_string_lossy` 或字节存 BLOB，**决策点**）。
5. **watcher**：notify crate（新依赖）监听 scan root；事件批处理 + 增量扫描。
**验收**：`hmp scan` 两次扫描缺文件标 missing；`library tracks --search` 可查；专辑/歌手聚合正确；移动文件后重扫不产生孤儿（指纹命中）。
**风险**：高（schema 迁移 v3 + 多 crate 改动 + CLI 面扩）；**必须**拆独立详细计划，建议 3-4 个 Task 组。

## 里程碑 F：LibraryPlaylist 播放源（本地歌单可播放）

**目标**：本地 SQLite 歌单成为播放源（审计 P1 #8；"能管理，不能播放"）。
**现状锚点**：
- `crates/hmp-core/src/ipc.rs:20` `PlayRequest::Playlist(PlaylistId)` 由 `QqSourceResolver` 按 QQ songlist 拉取（player.rs:402）；本地歌单无播放源。
- `playlist_tracks` 表：`(playlist_id, track_id, position, added_at)`——无唯一约束？需核实（同曲重复是否允许；若无唯一约束可插重复，但 `add_playlist_track` 的 upsert 语义需查）。
**方案**：
1. hmp-core：`PlayRequest::LibraryPlaylist(i64)` 新变体（或复用 PlaylistId + provider 判断——**决策点**：审计建议显式拆分 RemotePlaylist/LibraryPlaylist）。
2. player.rs：`CompositeSourceResolver` 分发 LibraryPlaylist → 从 SQLite `playlist_tracks JOIN tracks` 读 `TrackRef { provider, id }` 列表 → 转 stub。
3. `playlist_tracks` 加 occurrence id（自增主键）支持重复曲目与真实顺序（审计建议）；`add_playlist_track` 不再去重。
**验收**：`hmp play playlist:<id>`（本地歌单）播放；重复曲目按序出现；e2e。
**风险**：中；依赖：E 的 tracks 模型稳定后做（本地曲目 identity 未定时做了要返工）。

## 里程碑 G：播放器体验收尾（审计第 6 步）

**目标**：Previous 曲首行为、输出设备选择、gapless/preload、ReplayGain。
**现状**：MPRIS 规范项已修（批 1）；`Previous` 无"播放 >3s 先回曲首"行为（engine.rs `navigate_prev` 直接上一首）。
**方案**（按序）：
1. Previous 曲首语义：`navigate_prev` 若当前 position > 3s → 仅 seek(0) 不换曲。
2. 输出设备选择：`PlayerCore::new_with_sink` 已有注入点；CLI/配置暴露（`config.toml [audio] sink`）。
3. gapless/preload：`load_and_play` 前预解析下一首 uri（SourceResolver 加 preload 方法）——**依赖 A 的 generation 稳定**。
4. ReplayGain：lofty 读 RG 标签 → volume 补偿（E 的元数据扩展后做）。
**风险**：低-中；依赖：1 独立；2 独立；3 依赖 A；4 依赖 E。
