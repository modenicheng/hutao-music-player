# 任务书 · 实体化（§30.2.6 phase 2，存储/入库部分）

> 依据：`docs/AUDIT.md` §30.2.1、§30.2.3、§30.2.5、§30.2.6 phase 2；前置 phase 1 见 §32.1。
> 本任务只做**存储层与入库**：实体表、迁移回填、按实体 id 查询。桌面导航（`SongRow`、
> `Nav.param`、艺人/专辑页）由下一个任务接，不在本任务范围。

## 背景

phase 1 已把 QQ 的 `singer[].mid` 与 `album.mid` 落进 `track_artists.artist_mid` /
`tracks.album_mid`，但：

- 没有 `artists`/`albums` 实体：歌手/专辑仍是曲目行上的文本，本地同名专辑靠
  （专辑, 专辑歌手）分组“看起来”分开了，但没有稳定 id。
- `track_artists` 只有（track_id, artist, artist_mid, position），没有 `artist_id`；
  `tracks` 没有 `album_id`。
- 桌面只能按展示名猜（§30.2.3 第 3 条），点歌手会「最长包含匹配」落到错误页面。

## 目标 schema（v10）

```sql
CREATE TABLE artists (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  sort_key TEXT
);
CREATE TABLE artist_keys (
  artist_id INTEGER NOT NULL REFERENCES artists(id) ON DELETE CASCADE,
  provider TEXT NOT NULL,          -- 'qq' | 'local'
  provider_key TEXT NOT NULL,      -- qq: singer mid；local: 歌手名
  PRIMARY KEY (provider, provider_key)
);
CREATE TABLE albums (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  album_artist_id INTEGER REFERENCES artists(id),
  year INTEGER
);
CREATE TABLE album_keys (
  album_id INTEGER NOT NULL REFERENCES albums(id) ON DELETE CASCADE,
  provider TEXT NOT NULL,
  provider_key TEXT NOT NULL,      -- qq: album mid；local: 归一后的（专辑, 专辑歌手）
  PRIMARY KEY (provider, provider_key)
);
ALTER TABLE tracks ADD COLUMN album_id INTEGER REFERENCES albums(id);
ALTER TABLE track_artists ADD COLUMN artist_id INTEGER REFERENCES artists(id);
```

- `user_version` 9 → 10；迁移逐级事务、幂等；旧库可直接升。
- 索引：`artist_keys(artist_id)`、`album_keys(album_id)`、`tracks(album_id)`、
  `track_artists(artist_id)`（按实际查询补，不要滥加）。

## 实体身份规则（必须固定，桌面会依赖）

- **provider = qq**：key 用 mid（`singer[].mid` / `album.mid`）。mid 为空/纯数字 fallback
  时按 local 名称键处理（phase 1 已知的极少数情况）。
- **provider = local**：歌手 key = 标签歌手名原文（比较用 `NOCASE`）；专辑 key =
  `lower(title) + "\u{1f}" + lower(album_artist 或 artist)`，避免同名专辑合并。
- **跨 provider 归一**：按 key 查不到时，先按名称（歌手名 / 专辑 title+album artist，
  `NOCASE`）找现有实体并挂 key；找不到才新建。这样同一歌手/专辑不会因为本地与 QQ
  各来一条而分裂成两个实体（具体匹配策略写进注释与测试）。
- 专辑的 `album_artist_id`：有 `album_artist` 时解析到该歌手实体；否则用曲目首个
  歌手；都没有则 NULL。

## 迁移回填（v10 内完成，一次性）

1. 从 `track_artists` 的 `(artist, artist_mid)` 去重建/找 artists + keys，回填
   `track_artists.artist_id`。
2. 从 `tracks` 的 `(album, album_artist 或 artist, album_mid)` 去重建/找 albums + keys，
   回填 `tracks.album_id`；空专辑名跳过。
3. 回填后校验：每个非空 `track_artists` 行的 `artist_id` 非 NULL；每个有专辑名的
   `tracks` 行 `album_id` 非 NULL。迁移失败整体回滚（现有逐级事务模式）。

## 入库（写路径）

- `upsert_track` 与 `upsert_tracks_batch`：在同一事务内解析实体（专辑 + 歌手），
  写 `tracks.album_id`、`track_artists.artist_id`；`artist_mid`/`album_mid` 继续保留。
- `write_track_artists` 的签名扩展为带 `artist_id`（或内部解析），保持“mid 为 NULL
  时按同名旧行保留”的 phase 1 语义。
- 本地 `apply_local_meta` / `add_local_file`：用 local key 建实体。
- 批量缓存（`TrackMeta` 快路径）没有 mid 时不要用拼接展示串压成单歌手（phase 1
  的既有约束继续有效）。

## 查询接口（桌面下一任务会调用）

- `library_artists()` 返回 `ArtistGroup { id, artist, artist_mid: Option<String>, track_count }`
  （保留 `artist` 字段名；新增 `id`/`artist_mid`）。
- `library_albums()` 返回 `AlbumGroup { id, album, artist, album_mid, track_count, year, cover_uri }`。
- `artist_tracks_by_id(id)` / `album_tracks_by_id(id)`：与现有按名查询同口径（JOIN
  `local_files`、排序、`missing` 字段），但按实体 id 命中。
- `artist_by_id(id)` / `album_by_id(id)`：取展示名/album_artist/year/mid。
- 现有按名查询（`local_tracks_by_album`/`local_tracks_by_artist`/`library_albums(search)`）
  保持可用，桌面切换前不能破坏。

## 验收测试（必须）

- 迁移 v9→v10：构造含 QQ（有 mid）与本地行的 v9 库，升级后实体/键/关联齐全；
  重开幂等；`user_version == 10`。
- 同名不同专辑歌手：两条本地曲目 → 两个 album 实体、两个 key；同名同专辑歌手共享一个。
- 跨 provider：先本地「周深」再 QQ 同 mid 不同名/同名，按规则归一到同一实体或
  各自实体（按你实现的规则写死断言，并注释理由）。
- 入库幂等：同一 TrackRow upsert 两次，实体/键/关联不重复。
- QQ 与本地 `artist_refs`/`album_mid` 都写对；空 mid 不产生空 key。
- 按 id 查询：`album_tracks_by_id` 只回该实体曲目；同名专辑另一实体不混入。
- 全仓 `cargo fmt --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、
  `cargo test --workspace` 全绿（逐 crate）。

## 约束

- 只改 `hmp-storage`（必要时 `hmp-daemon` 的调用适配），不改桌面/UI；不改 IPC。
- 不加依赖；不做 phase 3（`track_sources`、local-first 回退、手动关联）。
- 每个逻辑改动单独 commit（英文 Conventional Commits）；迁移与回填一个 commit，
  入库一个，查询一个，测试可随各项。
- 迁移后 `PRAGMA foreign_keys = ON` 的既有行为不要破坏；删除策略按现有 schema 惯例。
